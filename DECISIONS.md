# Decisions

Judgement calls made without you. Overturn any of them at breakfast — the reversal cost is in
the last column. Newest at the bottom.

| Date | Decision | Why | How to reverse |
| --- | --- | --- | --- |
| 2026-07-30 | Owner approves every request; guests never self-confirm. | It's a family house, not a rental. The owner's real objection to a booking is rarely "those dates are taken" — instant-book removes the conversation that matters. | Add an `autoApprove` flag on `houses` and skip the `pending` state. The data model already supports it: `pending` simply stops being written. Small change, mostly UI. |
| 2026-07-30 | No payments, deposits, or cancellation policy. | Nobody charges their cousin. Stripe would add an account, a webhook, a refund story, and a legal surface for zero value in v1. | Genuinely new work, not a flag flip. Would need Stripe, a `payments` table, and a refund flow. Assume a week, not an evening. |
| 2026-07-30 | Language is per-house, not global i18n. Owner picks `en` or `tr`; the guest page, guest emails, and the generated prompt render in it. Owner dashboard is English only. | One house has one set of guests who share a language. Full i18n means a library, locale routing, and translating an admin UI only you will ever see. | Two JSON dictionaries and a `t(key, lang)` helper — no library to rip out. Adding a locale is a third JSON file. Localising the dashboard means passing the owner's language instead of the house's. |
| 2026-07-30 | The guide is written by a copy-paste prompt, not an AI API call. | Costs nothing, needs no keys, works with whatever model you already pay for, and the owner sees exactly what's being asked on their behalf. An API call adds a metered dependency to a feature used once per house. | `lib/guide-prompt.ts` already produces the full prompt string. Swapping in a model call means sending that string and feeding the reply to the existing parser — the parser and editor stay. |
| 2026-07-30 | Double-booking is prevented by a Postgres exclusion constraint, not by application locking. | Two pending requests on the same week is correct — the owner should see the clash and choose. The constraint fires only on approval, so the second approval raises a database error the action catches and turns into "Those dates were taken while you were deciding." Race-proof without transactions or locks in app code. | Drop `bookings_no_overlap` and check overlap in the action instead. Not recommended: that reintroduces the race the constraint exists to close. |
| 2026-07-30 | `lib/storage.ts` has two drivers, `local` and `blob`, chosen by `STORAGE_DRIVER`. Local is the default for now. | Blob provisioning may need a TTY, and a failed provision must not leave the image flow untestable overnight. Local disk keeps upload, render, and delete verifiable end-to-end. | Set `STORAGE_DRIVER=blob` and `BLOB_READ_WRITE_TOKEN` in `.env.local`. One variable. Existing local images won't migrate themselves — re-upload or copy them across. |
| 2026-07-30 | Kept the working name "Yazlık" and the slug `yazlik` for now. | Something had to go in `package.json`, the Neon project, and the repo folder, and picking a name isn't a call to make while you're asleep. | Cheap today, annoying after deploy: rename the folder, `package.json` name, and the Neon project. No user-facing copy depends on it yet. Listed in `HANDOFF.md` under "Needs you". |
| 2026-07-30 | Schema is applied with `drizzle-kit push` plus idempotent SQL in `db/sql/`, not a generated migration chain. | The schema is still moving — Phase 2 adds better-auth's tables and the `houses.owner_id` foreign key. Generating migrations now would produce a chain that immediately needs rewriting. `db/sql/001_bookings_no_overlap.sql` holds the exclusion constraint and is safe to re-run. | Once the schema settles (end of Phase 2), run `pnpm db:generate` to start a real migration chain and keep `db/sql/` for constraints Drizzle can't express. |
| 2026-07-30 | `houses.owner_id` is a plain `text` column with no foreign key yet. | `db/auth-schema.ts` doesn't exist until the better-auth CLI generates it in Phase 2, and the schema can't import from a file that isn't there. | Phase 2 adds `.references(() => user.id, { onDelete: "cascade" })` — the exact line is marked with a comment in `db/schema.ts`. |
| 2026-07-30 | `destructive` red survives as a second hue despite "exactly one accent". | Decline and error paths need to read as different in kind, not just in weight. A neutral-only decline button is genuinely ambiguous next to a neutral cancel. | One line in `app/globals.css`: point `--destructive` at the neutral ramp. |
| 2026-07-30 | `experimental.serverActions.bodySizeLimit` raised to 10MB in `next.config.ts`. | The plan's answer to multi-megabyte phone photos was uploading straight to Blob from the client. With `STORAGE_DRIVER=local` there is no CDN to upload to, so the bytes cross a Server Action, whose default limit is 1MB — smaller than any real phone photo. 8MB stays the enforced ceiling in `save()`; 10MB is headroom for multipart overhead. | When Blob is provisioned and the uploader moves to `@vercel/blob/client`, delete the line. |
| 2026-07-30 | `storage.remove()` never throws, and `deleteImage` removes the row even when the file is already gone. | An orphaned file is recoverable; an orphaned row shows the owner a photo that 404s and a delete button that fails forever. The row is the part that matters. | It's a `try/catch` in `lib/storage.ts`. Removing it makes deletes fail loudly instead. |
| 2026-07-30 | The 12-photo gallery cap is held by `SELECT … FOR UPDATE` on the house row, not by counting rows. | `<input multiple>` fires concurrent uploads; a count-then-insert races and overshoots. Verified: 15 simultaneous uploads onto a gallery holding 1 produced exactly 12 rows, 11×201 and 4×409, and the refused uploads deleted their own files. | Swap the lock for a count if you ever want the cap to be advisory. |
| 2026-07-30 | Local uploads are served from unguessable URLs, not authenticated ones. | Matches Vercel Blob's `access: "public"` posture, so behaviour doesn't change when the driver flips. The plan's privacy split is enforced by *not querying* guests-only photos on the public page — never by the storage layer. | If photos ever need real access control, it has to be added at both drivers, and Blob private access changes the delivery cost. |
| 2026-07-30 | Dev server is pinned to **port 3100**, not 3000. | Port 3000 on this machine is held by an unrelated `mcp-excalidraw-local` process, so `next dev` silently fell back to 3001 while `BETTER_AUTH_URL` still pointed at 3000 — sign-out posted to the wrong origin and failed with no error. Pinning both makes it deterministic. | Change `dev` in `package.json` and the two URLs in `.env.local` back to 3000, once something else isn't holding it. |
| 2026-07-30 | Magic link doubles as sign-up — a first-time address creates an owner. There is no separate sign-up screen. | The plan says any owner can sign up, and a second screen asking the same single question would be pure ceremony. | Set `disableSignUp: true` in the magicLink plugin in `lib/auth.ts` and add an invite path. |
| 2026-07-30 | The owner menu is a bottom sheet rather than a dropdown, and has no visible close button. | `dropdown-menu` isn't installed and a bottom sheet is the better phone target anyway. shadcn's sheet close button is 28px, under the 44px floor, and lives in a file agents don't own — so it was removed rather than shipped undersized. Escape and tapping outside both close it. | Add a 44px close control to `components/ui/sheet.tsx`, or install `dropdown-menu` for wider screens. |
| 2026-07-30 | Type scale remapped to 13/15/17/22/28, which shifts every shadcn component (their `text-sm` was 14, now 15). | The plan specified the scale. Leaving Tailwind's defaults would have meant two competing scales in one codebase. | Revert the `--text-*` block in `app/globals.css`. Note `2xl`/`3xl` were extended to 34/40 so the ramp stays monotonic — undo those together. |
